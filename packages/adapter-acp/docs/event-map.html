Half of this adapter's events are not observations. Turn boundaries and reasoning completion are emitted by the driver, around our own prompt() call — not read from the agent. That has a direct consequence: a turn the user starts by typing into the native TUI is invisible. The agent keeps reading idle while it works, because nothing told us a turn began.

Untracked

Any session/update kind outside the seven above hits the default branch and becomes adapter.native-event — retained verbatim per ADR-008, counted in counters.unknownEvents, invisible. In the ACP surface that includes plan updates, available-command updates, and mode changes. Unrecognized JSON-RPC methods on the connection take the same path.

Gaps worth knowing

No context-window.invalidated. ACP is the only adapter that never emits it, so a compaction leaves a stale CTX reading rather than clearing it — the badge keeps showing a number that is no longer true.

Union members never produced: session.ready · session.exited · reasoning.summary · tool.requested · subagent.started · subagent.stopped · task.created · task.completed · context-window.invalidated · process.started · workspace.changed · notification.

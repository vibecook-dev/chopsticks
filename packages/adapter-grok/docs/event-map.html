Do the two sources double-count? No — verified

Both sources could describe the same turn: the ACP driver emits turn.started when we call prompt(), and the observer emits one when it sees a prompt land, including ours. They do not collide, because backend.ts:263 filters the ACP stream to an explicit allowlist whenever the observer is running:

permission.requested · permission.resolved · context-window.updated · context-window.invalidated · session.environment.updated

Everything else from ACP — turn.*, assistant.message, tool.*, reasoning.* — is dropped before it reaches the reducer. The split is stated in the code itself: “the native log owns TUI conversation and lifecycle. ACP remains the live authority for host-side permissions and standard context usage.” The observation level moves to native-log to match.

The Claude adapter resolves the same way and is documented on its own page: the live transcript path keeps only assistant records, and turn.* is projected solely on resume under replay: true. Neither adapter double-counts, and neither needed a live session to prove it.

Coverage relative to the union

Grok has the widest coverage of any adapter, because it is ACP plus a native observer: it is the only one to reach both session.exited and process.exited, and it recovers context-window.invalidated, which plain ACP lacks.

Union members never produced: reasoning.summary · tool.requested · subagent.started · subagent.stopped · task.created · task.completed · process.started · workspace.changed · notification.
